# Dafter agent context

Realtime AI media toolkit (agents, translation, transcription, sealed recording) behind one API, one SDK, one config document. Read `docs/dafter.md` first; section 6 is the delivery plan.

## Layout

- `schemas/`: the only source of truth. All language types are generated from it.
- `go/` (control plane, state, egress, seal) and `python/` (agent runtime, providers, batch, evals). They touch only at the resolved config document and the event envelope.
- `python/` workspace members: `dafter_core` (generated contract), `dafter_providers` (one subpackage per vendor, `registry.py` maps `agent.pipeline.<stage>.provider` to a factory; nothing else imports a vendor plugin), `dafter_runtime` (the agent worker, pool `dafter-py`), `dafter_evals` (scripted live-agent harness, `uv run dafter-evals`; it spends provider credits, run it deliberately; `uv run dafter-wer` scores a transcript against a known clip offline, `testdata/wer/`), `dafter_batch` (the transcript after the call, `uv run dafter-batch <session>`; spends batch provider credits), `dafter_scribe` (the silent scribe, pool `dafter-scribe`, `uv run dafter-scribe start`; notes, turn scores and minutes from the live captions; spends LLM credits). One run per config change: `--overrides` for the session, `--out` for the report, `--baseline` an earlier report to diff against; `--scenarios` adds `paused` (each `script.paused` sentence said in two halves with a 300 ms hesitation) to the default ones, and `early_endpoints` counts turns the agent took before the caller's last word. The report names the clock behind every number: `caller` (the probe's, from the caller's last word as sent: the gap to the first agent audio, the end of turn to the `thinking` state, the reply after it, and the barge-in stop from agent state events) and `worker` (p50/p95 of every `agent.turn_metrics` layer, anchored at the end of speech the STT reported; Sarvam's carries no speech end time, so there it is the event's arrival and the end-of-turn and transcription layers read near 0). The go/no-go against the session's `budgets` judges the reply on the caller gap, never on the worker's `e2eLatencyMs`. Offline and per language: `uv run dafter-asr` scores the STT a job vector names on the pinned public samples in `testdata/asr/` (Kathbath for hi, kn, mr, te; Svarah for en-IN, gated behind `HF_TOKEN`), audio fetched by HTTP range into the git-ignored `testdata/asr/audio/`, spending STT credits under `--max-inr`; `uv run dafter-scorecard` folds `dafter-asr` and `dafter-evals --out` reports (and human naturalness ratings) into one card per language and stack, listing what is still pending.
- `go/tools/enumgen`: emits enum constants for both halves. `Makefile` is the entry point; `.github/workflows/ci.yml` runs it.
- `testdata/`: fixtures both halves read, so a cross-language claim is checked on both sides rather than asserted on one. Each directory has a README saying what it pins; `testdata/rfc8785/` is vendored verbatim and must never be edited or reformatted.

## Generated files: never hand-edit, never commit

Produced by `make generate`, git-ignored, policed by `make generate-check` (first step of `make check`):
`go/internal/**/*_gen.go`, `python/dafter_core/src/dafter_core/enums.py`, `go/internal/schema/schemas/`, `python/dafter_core/src/dafter_core/_schemas/`.
Every target regenerates before it runs, so a clone only needs `./scripts/setup.sh` once. See the `schema-change` skill.

## Commands

- `./scripts/setup.sh` once per clone (a fresh checkout does not compile until it runs)
- `make check` (the Go, test client and Python checks CI runs)
- Go: `make build vet lint test tidy`
- Test client: `make js-test` (Node 20+, `node --test` over `go/cmd/dafter-control/jstest/`, which loads the browser scripts into a `vm` context with stub rooms; no packages)
- Python: `make py-lint py-test` (ruff, mypy strict, pytest via `uv run --frozen` from `python/`)
- Test client: `make js-test` (Node's built-in runner over `go/cmd/dafter-control/jstest/`). The main screen holds only the call (language, LLM, the fillers, backchannel and normalization toggles from `SPEECH_TOGGLES` in `agent-speech.js` sent as session overrides of the existing config fields, start, media, leave); every other control lives under the one closed Advanced section, pinned by `jstest/layout.test.mjs`.

## Rules enforced in code, kept identical on both halves

- Validate the raw document, then decode: `config.Parse`, `events.Parse`; `config.parse`, `events.parse_event`.
- Unknown fields rejected: schemas close with `unevaluatedProperties`; Go also uses `DisallowUnknownFields`.
- A schema file stays under 500 lines like code, so a family of event payloads goes in its own file under `schemas/events/v1/` (as `transcript.schema.json` and `scribe.schema.json`), applied from the envelope's `allOf` by `$ref`, and a config block likewise under `schemas/config/v1/` (as `language-switching.schema.json`, `backchannel.schema.json`, `scribe.schema.json` and `telephony.schema.json`), referenced by its `$id`. Go walks every embedded schema; Python needs the file in `_FILES` (`dafter_core/validation.py`).
- Cross-field rules the schema cannot express are one table per half, `go/internal/config/rules.go` and `python/dafter_core/src/dafter_core/rules.py`, every broken rule reported with its pointer: sealed forbids agent; an addressing mode that waits to be called needs a name, and a near miss may not be the name or an alias; recording needs consent artifact; `session_create` start needs `room_composite` layout; `media.encryption.mode` must match what `privacyMode` implies; end-to-end encryption forbids recording, because every egress layout is server-side; `provider_endpointing` forbids `turn.localVadEnabled`, because the recognizer decides the turn; `transcription.mode` other than `off` needs `transcription.consentArtifactId`, is forbidden when sealed, `live`/`both` needs the agent (its worker transcribes), `after_call`/`both` needs track recording and a `transcription.batch` provider (vectors in `testdata/transcription/`); `agent.languageSwitching` enabled must list the session's own language; `scribe.enabled` needs `scribe.consentArtifactId`, transcription `live`/`both` (it reads the captions), a `scribe.llm`, a pool other than the agent's, and is forbidden when sealed (vectors in `testdata/scribe/`); telephony forbids end-to-end encryption (at `/channel`, the SIP bridge decodes every frame) and a recorded telephony session needs the agent, which tells the caller; `telephony.phoneGuests` other than `off` needs a trunk, forbids end-to-end encryption and is forbidden on the telephony channel (all at `/telephony/phoneGuests`), and a recorded session with phone guests needs the agent (vectors in `testdata/telephony/`).
- `privacyMode` decides encryption: resolution stamps `media.encryption` so the hashed document states it. Under `e2ee` the control plane mints one shared key per session and returns it as `encryptionKey` beside the token, never inside the resolved document, which is hashed, stored and handed to every joiner. Who receives it derives from the role and the mode like a token grant, never from the request: `DisclosesKeyTo` in `go/internal/config/config.go`. The agent worker never gets it through the media server (not dispatch or job metadata, attributes or data): it asks `POST /sessions/{id}/agent/key` at job start with the worker credential `DAFTER_WORKER_SECRET` and the job's `configHash` (`go/internal/control/worker.go`, `python/dafter_runtime/src/dafter_runtime/control.py`), and joins with the browser's key provider settings (raw 32-byte key, HKDF, ratchet window 0, failure tolerance -1); the scribe asks `POST /sessions/{id}/scribe/key` the same way (`ControlPlane(role="scribe")`). At rest the key is sealed with AES-GCM under `DAFTER_STATE_KEY` (`go/internal/state/keys.go`), the session id as associated data.
- Error messages safe to log (no name, email, phone, transcript): `schemas/errors/v1/error.schema.json`. Report every problem, located by JSON pointer.
- Identifiers are opaque patterns (`schemas/common/v1/ids.schema.json`, minted in `go/internal/ids`); credentials are `secret://` refs; region tokens opaque. Real credentials reach the process through the environment only. The worker resolves `secret://.../<vendor>/<name>` to the env var `<VENDOR>_<NAME>`, and only to a provider key on `PROVIDER_CREDENTIALS` that the stage's vendor binds (`credentials.resolve`; Sarvam binds `SARVAM_API_KEY`); a ref naming anything else, such as a `DAFTER_*`, LiveKit, worker or storage secret, is refused by pointer before the worker joins, whatever its path says. The tenant segment of a ref is not read. An OpenAI-compatible LLM never takes a URL from the document: each entry of the operator's table `python/dafter_providers/src/dafter_providers/openai_compat/endpoints.json` is a vendor of its own, named by its key and bound to one https base URL and exactly one provider key, and a `credentialRef` that is not that endpoint's key is refused. The eval catalog (`dafter_evals/screen/candidates.json`) names the same vendors and holds no URL or key of its own.
- Config resolution is layers then axes, `go/internal/config/resolve.go`: defaults, the named agent (`agents` kind, `go/internal/config/agents.go`; none named resolves as the defaults state), tenant, profile (the request's, else the agent's), each axis's `tuning` (language, then channel), session overrides, then each axis's `overlay`. Tuning is what a session may change, such as the turn strategy and turn constants, so an override wins over it; an overlay pins what the axis must decide, such as the language's pipeline and batch transcription provider and the channel's media, and lands last. Each focus language states its own route (STT, LLM, TTS voice) and turn constants; semantic turn detection only where the on-device detector covers the language (`test_languages.py` reads the catalog). An override an overlay would replace is refused, located by pointer, never dropped. A session override never names the endpoint or credential a stage uses, or the SIP trunk: a stage's `credentialRef`, `options.endpoint` or `options.baseUrl`, or `telephony.trunk`, in the overrides is refused by pointer (`operatorOnlyProblems`), like the ids the control plane mints. It is a rule on the override layer, not the resolved document, and only Go resolves, so it has no Python half.
- Layers replace lists, except `/agent/addressing/nearMisses`, which every layer adds to (`unionNearMisses`), so a tenant or agent near miss never drops the defaults'.
- LLM routes: the catalog's `llms` table (key `provider/model`, a full provider ref) is the only way a session picks its LLM. `POST /sessions` names one in `llm`; resolution lands it whole over `agent.pipeline.llm` after the overlays and stamps `llm` in the document (`go/internal/config/llm.go`); an override may not name or tune it. `groq`, `openrouter`, `google` (AI Studio, key `GEMINI_API_KEY`), `opencode_zen` and `openai` are vendors built from `dafter_providers/openai_compat/endpoints.json` (one https host and one key each), reporting usage under their own name. Each route states the least thinking its endpoint allows (Groq qwen `reasoningEffort` `none`, gpt-oss `low`, OpenRouter `extraBody.reasoning.enabled` false, Gemma 4 on AI Studio `thinking_level` `minimal` under the literal body key `extra_body`, since it refuses a thinking budget or effort; lfm-2.5 refuses to turn reasoning off, so `effort` `low` with a larger `maxTokens`). A new model is one line in the catalog's `llms` and one in `LLMS` in the test client's `agent-llm.js`, pinned to the catalog by `jstest/llm.test.mjs`, and the page names the LLM the agent reports, red when it differs from the config. Each compat vendor holds one HTTP/2 connection per job (`openai_compat/wire.py`; over HTTP/1.1 the framework abandons the stream body and every turn reconnects) and logs every request as `llm request` (settings, status, HTTP version, `headers_ms`, rate-limit headroom, never message text), so a slow turn shows whether the time was the provider's. Models copy the `[Speaker 1, to you]` turn labels; `labels.py` strips a label at any line start in `llm_node`, so it is never spoken or shown.
- The config hash is RFC 8785 then SHA-256 with `configHash` stripped, mirrored in `go/internal/config/hash.go` and `python/dafter_core/src/dafter_core/hashing.py`. Both halves are pinned to the vectors in `testdata/`; changing either without the other fails on its own side.
- Token grants derive from the role and never from a client request, and no role is ever issued a room-admin, room-create, room-list, room-record or ingress grant: `grantsFor` in `go/internal/transport/livekit.go`. Every permission is stated rather than left unset, because the media server grants an absent permission by default. The one token that carries `roomRecord`, `roomCreate`, `roomList` or `sip.call` is the per-call service token in `go/internal/transport/egress.go`, a separate claims type that is never returned to a client.
- A joiner's participant id is minted by the control plane, or, when the join names a device key, derived from the session and that key under a server key (`participantFor` in `go/internal/control/identity.go`), so one browser rejoining or opening a second tab replaces its own connection instead of adding a participant. Display names travel only on the `dafter.name` data topic, never in a token.
- Recordings are started and stopped by the control plane from the session's stored config (`POST /sessions/{id}/recording/start|stop`, `go/internal/control/recording.go`) over the media server's Twirp JSON API, no vendor SDK. Request JSON is pinned in `go/internal/transport/testdata/egress/`; the server answers with proto field names (`egress_id`).
- The media server posts signed webhooks to `/livekit/webhook` (`go/internal/transport/webhook.go`), handled off the request in `go/internal/control/webhook.go`: `track_published` for an audio track starts that voice's own track egress when `recording.tracks` is on; `participant_joined` by a `p_` id marks the session joined; `egress_ended` settles a recording; `room_finished` (sent `departure_timeout` seconds after the last person leaves, agents and recorders not counting) ends a joined session, stops its recordings and closes its dial-in, and an ended session refuses joins with `session_ended` (410). Recording state is serialized per session, never globally, so a slow egress start cannot hold up another call's join.
- The binary serves `MetricsHandler`, not `Handler`: a route must be registered in `go/internal/control/metrics.go` too, and the control tests drive that mux.
- The noise filter a session resolves to is applied by the publishing client from one registry, `NOISE_FILTERS` in `go/cmd/dafter-control/client.js`: a member of `noiseCancellation` needs an entry there or it does nothing. The browser's own suppression and a processor are never both on, because stacking suppressors degrades speech; echo cancellation is separate and stays on. A processor is attached to the microphone track before it is published, never after. Worklet and WASM assets come from a pinned CDN URL beside the SDK pin, and every way loading them can fail falls back to `native` visibly (the call shows the active filter). `rnnoise_gated` adds the near-voice gate (`voice-gate.js`, served by the control plane), which needs automatic gain off: AGC would lift the room up to the caller's level whenever they are quiet.
- A microphone can return the agent's own voice (speakerphone, phone line, a meeting room: no echo cancellation on that path). Every hearing path runs `OwnVoice.hearing` (`python/dafter_runtime/src/dafter_runtime/own_voice.py`) first: a transcript whose speech began while the agent spoke and that is mostly the agent's recent words is dropped, and once a participant has echoed, voice activity alone no longer pauses or cuts the agent and a fragment over it needs three new words. A new listening path that skips it lets the agent answer and interrupt itself. `dafter-evals --echo <gain>` reproduces such a line.
- A session is written to the store before its token is minted. A token issued for a room whose config was never stored lets a worker join a session nobody can explain afterwards.
- The catalog lives in SQLite as append-only revisions of whole documents per kind, published as numbered releases (`go/internal/configstore`). `catalog.json` seeds an empty store as release 1, and its `defaults` and `llms` stay in the repository, imported on start; the rest is edited through the admin API (`go/internal/admin`, own listener `DAFTER_ADMIN_ADDR`, bearer `DAFTER_ADMIN_TOKEN`). Every write and publish passes `go/internal/configcheck`: the document's shape, a pasted-secret screen, then a dry-run resolve of every affected tenant x agent x profile x language x channel. Running control planes poll and swap the live release in (`configstore.Live`); a session stores its `release_id` beside its hash.
- An agent session is dispatched after it is stored and before any token is minted (`dispatchAgent` in `go/internal/control/control.go`); a scribe session gets a second dispatch to `scribe.pool` with the same document right after (`dispatchScribe`, `scribe.go`), and a failed one is logged and never fails the call. The job metadata is the stored, hashed document byte for byte; the worker validates it, re-hashes it and refuses a mismatch (`load` in `python/dafter_runtime/src/dafter_runtime/plan.py`) and calls the control plane only at job start, for the session key and to report a refusal, never mid-turn. `CreateDispatch` needs `roomAdmin` on the one room, carried only by the per-call service token in `go/internal/transport/dispatch.go`; the request JSON is pinned in `go/internal/transport/testdata/dispatch/`. `testdata/agent/` pins one job per focus language (hi, en-IN, kn-IN, mr-IN, te-IN) that both halves read.
- The agent is brought into or out of a running session by `POST /sessions/{id}/agent/start|stop` (`go/internal/control/agent.go`). The stored config is the authority: a start is refused when the stored document has the agent off, and both are refused for a sealed session; the body takes no fields. A start first recalls the pool's existing dispatches, so the room holds one agent. `RecallAgents` in `go/internal/transport/dispatch.go` deletes only dispatches of the session's pool (every room also carries a default dispatch with an empty agent name) and skips a closed room, found with a `roomList`-only service token, because listing a closed room's dispatches waits on a node that hosts nothing.
- The worker refuses a job it cannot run before it joins (`plan`): pool mismatch, non-cascaded mode, e2ee without a worker credential or under a key model other than `server_shared`, an unregistered provider, a language a provider does not declare, a turn strategy it cannot run, a local VAD the pipeline does not name, an unknown persona, addressing `on_device`, language switching with an STT that cannot identify a language or a listed language without a persona or provider. Every refusal, a stage that cannot be built after accepting (a missing provider key) and a withheld key after accepting are posted to `POST /sessions/{id}/agent/refusal` as an error document; `GET /sessions/{id}` returns it as `agentRefusal` until the next invite, and the test client shows it (`agent-refusal.js`). Providers are constructed and TTS prewarmed before `ctx.connect`.
- The agent's name is `agent.name` (catalog: Nivya) and nothing else names it: the worker joins under it (the tile, transcript and caption labels read the participant name) and `persona_for` puts it in every persona and greeting (a greeting says it in its language's own script when `addressing.aliases` has that spelling, `spelled_for`), and the name matcher listens for it (`personas.py`, one `Script` per persona and language). The worker says the greeting only when `agent.greets` is true, default off. "Dafter" is the product, never the agent. Nivya is a woman: the catalog voice is Sarvam `priya` in every language (the provider falls back to it too), and every line the agent speaks or is told to speak refers to herself in the feminine (`FEMININE` in `personas.py`, pinned by `test_personas.py`).
- Sarvam specifics live in `python/dafter_providers/src/dafter_providers/sarvam/`: the LLM goes to `https://api.sarvam.ai/v1` (the plugin's default `/v2` is beta-gated) with `reasoning_effort` null, because thinking on spends the whole token budget on reasoning and says nothing; `FinalFirstSTT` holds end of speech until the final transcript, because Sarvam sends `vad.speech_end` first and the framework would commit a stale transcript; it releases end of speech with the final, and waits `finalGraceMs` (STT option) only for a final that is late. `SentenceTTS` swaps in a tokenizer that ends sentences at the danda, which the framework's does not, so TTS starts on the first sentence; bulbul:v3 takes pace (0.5 to 2), temperature (0.01 to 1 on the websocket) and a pronunciation dictionary's `dict_id` (TTS options `pace`, `temperature`, `styles` per situation, `dictionaryId`), no pitch or loudness; TTS option `firstSentenceAlone` sends a reply's first sentence to synthesis on its own, flushed at once however short, because Sarvam otherwise holds text under `minBufferSize` and the tokenizer holds a sentence under 20 characters until the next one ends (livekit-agents drops text pushed after a stream's `flush()`, so `FirstSentenceAlone` in `sentences.py` sends the sentinel itself and ends only that segment on Sarvam's first `final`); and its text preprocessing is always on. Sarvam's server VAD ends the turn; the local VAD (`agent.pipeline.vad`, the framework's bundled Silero in `dafter_providers/silero`, loaded once per process by `prewarm` in `worker.py`) is for interruptions only (`turn.interruption.localVadEnabled`, interruption mode `vad`). Strategy `semantic` runs the framework's on-device turn detector (`inference.TurnDetector`, `v1-mini`, dynamic endpointing) where `TURN_DETECTOR_LANGUAGES` in `plan.py` covers the language and falls back to provider endpointing elsewhere. STT option `mode` is `transcribe` or `codemix` (English words kept in Latin script, finals only); the catalog sets codemix for every Indic language. The plugin accepts only `saaras:v3-realtime` and its own list of 30 bulbul:v3 speakers.
- `agent.addressing` decides when the agent speaks (privacy consequences in `docs/dafter.md`, Recording, encryption, and governance); the catalog default is `transcript`, so a session answers every turn only when it states `always` (the evals harness does, `session_overrides` in `dafter_evals/connect.py`). The name it listens for is `agent.name`, its other spellings `addressing.aliases`. `always` is one AgentSession linked to one participant. `transcript` runs a voice session (LLM and TTS, no audio in, manual turns, started first so it is the primary) plus one listener AgentSession per human (`listeners.py`, record=False, its Agent raises StopResponse), because livekit-agents links a session to one participant; the listeners take the turns with the session's turn handling and share the job's one VAD and turn detector (`listening` in `called.py`), and the voice session keeps preemptive TTS; the framework cannot resume a reply across sessions, so `barge_in.py` pauses and resumes the voice session's room output itself: the caller's listener pauses the reply once the caller has talked for `interruption.minDurationMs`, a word heard (and `minWords`) cuts it, an acknowledgement that listener dropped resumes it at once and silence resumes it after `falseInterruptionTimeoutMs`; others' speech never touches it; the turn reaches the voice session as a user message carrying the listener's speech start and stop, end of turn and transcription delays (`heard` in `timing.py`), so `agent.turn_metrics` keeps every layer and `e2eLatencyMs`; `called.py` wires them, `addressing.py` (Gate) decides dormant or awake, `naming.py` hears the name (vectors in `testdata/addressing/`). The Sarvam realtime STT takes the name as its `prompt`; it has no key term list. Tools go through `tools.py` (Registry): speed and effect classes enforced in code, external and binding wait for the caller's own spoken yes (`consent.py`), binding also for an attested role, which the worker does not have yet, and calls run one at a time. A called session's `agent.state_changed` carries `dormant`, `wokenBy` (participant id) and `wokenVia`; the test client's Wake button sends `{"action":"wake"}` on data topic `dafter.agent`, and the sender is the packet's participant.
- Stage 2 (sounding human) is config, never constants: `turn.interruption.backchannel` and `agent.speech` in the schema, values in the catalog's defaults layer so a session may override them, and the TTS voice options (`pace`, `temperature`, `styles`) in each language's overlay beside its pipeline. Acknowledgements: the local VAD still pauses the agent at once; `backchannel.py` sieves the recognizer's events in the agent's `stt_node` (the listeners' too) and drops an utterance of listed phrases said while a reply is pending or playing, so it never becomes a turn or history, and livekit-agents resumes the paused reply after `falseInterruptionTimeoutMs` (always mode; its default `aec_warmup_duration` also ignores barge-in for 3 s from the first time the agent speaks in a session). An answer is the exception: when the reply the caller was hearing then plays to its end as a question (its text ends in `?`) within `backchannel.answerWithinMs` of played audio and the caller says nothing more, the held utterance is released into the same recognizer stream as their turn (`SessionFloor` counts played time from `agent_state_changed`, so a paused reply's silence does not count). Text: `speech_plan.py` is the last `tts_text_transforms` entry after the framework's markdown and emoji filters, holding text to sentence ends, stripping list numbering, applying `substitutions`, and under normalization `platform` the language's rules (Hindi only, `spoken_hindi.py`, vectors in `testdata/speech/`; the Hindi personas write digits, the English ones words); `provider` leaves digits to TTS. Voice: `delivery.py` classifies the caller's last turn (concern, greeting, neutral; the opening is a greeting) and the agent's `tts_node` calls `style()` on a TTS implementing `dafter_providers.Styled`. Fillers: after `fillers.afterMs` of `thinking` with no reply audio ready the reply's `tts_node` plays a phrase synthesized at session start ahead of the reply, never while anyone in the call is speaking (`Filler.hears` follows the session and every listener), and the registry's slow tools use the same phrases and delay; stored filler frames carry no synthesis stamp, and on a filler turn `agent.turn_metrics` says `filler: true`, e2eLatencyMs and replyGapMs count to the filler while ttsNodeTtfbMs and llmNodeTtfsMs are the reply's own (`Filler.reply_layers`). `agent.speech.expressive` is passed to `AgentSession(expressive=...)`, which livekit-agents 1.8.3 keeps off for any TTS without a markup dialect, Sarvam included.
- Stage 5 (multilingual): each focus language routes its own pipeline, voice and turn constants in the catalog (see config resolution above), and has personas in `personas.py`: the casual code-mixed register people speak on a call (Hinglish, Kanglish, Tenglish, Marathi mixed with English, Indian English), Indic words in native script and everyday English words (`EVERYDAY_ENGLISH`) in Latin script as bulbul:v3 and codemix STT expect, polite address, one or two short sentences, an AI only when asked, never an invented lookup or action; Hindi writes digits for `spoken_hindi.py`, Kannada and Telugu say prices, times and phone numbers in English words, Marathi amounts in Marathi and phone numbers in English, English in words. The kn, mr and te text needs a native speaker's review. Live switching is `agent.languageSwitching` (catalog defaults list the five, off; a session enables it): the STT then identifies the language (`Vendor.detects_language`, STT factory language `None`, Sarvam `language_code=auto`), `switching.py` switches on a final whose base language is listed, long enough (`minWords`) and confident enough (`minConfidence`), observed in the answering agent's `stt_node` (always) or per listener and applied when the voice answers that speaker (transcript); the `switch_language` tool pins a requested language. Followers: TTS `Multilingual.speak_in` (voice stays the session's), the speech planner's rules, fillers of the new language (synthesized on first use), and `llm_node` swaps in that language's persona per reply; turn constants and the turn detector stay the session's (the framework skips the detector per utterance for a language it does not cover). `agent.turn_metrics.language` is the language decided at the turn a reply answers.
- Transcription (`transcription.mode`: `off`, `live`, `after_call`, `both`) is two passes that never mix. Live captions are the realtime pass and never stored: `captions.py` follows each stage 3 listener session's `user_input_transcribed` (called mode through `Called`, always mode through `Transcribing` in `transcribing.py`, which runs the same listeners for every human without touching addressing, so the linked caller is heard by two STT streams) and the voice session's text output (`TextOutputOptions.next_in_chain`, released in step with the audio), and publishes `transcript.partial`/`transcript.final` on `dafter.events` with an opaque segment id, the speaker as participant id or agent, and the recognizer; the text is allowed in these events and never logged. The transcript of record is made after the call from each speaker's own track: `recording/start` for a track looks up its publisher (`RoomService/ListParticipants`, `recordings.go` in transport) and stores the speaker on the egress; `GET /sessions/{id}/transcription/sources` (worker credential) hands the batch pass finished attributed audio tracks as S3 SigV4 presigned URLs (`presign.go`, the object key from `Egress/ListEgress` `file_results`) and lists the rest as pending or skipped. A track egress ends on its own when its speaker leaves and the stack receives no media server webhook, so the sources call asks `Egress/ListEgress` for every attributed audio track and stores an ended one as stopped at its `ended_at`: `EGRESS_COMPLETE`, or `EGRESS_LIMIT_REACHED` with a file, is a source; `EGRESS_FAILED`, `EGRESS_ABORTED`, a limit with no file, or an egress the media server no longer knows is skipped with the reason; only one still running is pending. `recording/stop` treats an egress that already ended (the server refuses its stop with `failed_precondition`) the same way, and a stop naming an already stopped one answers it unchanged; `dafter_batch` runs the verbatim (Sarvam mode `verbatim`) and clean (`transcribe`) renderings through `batch_for` (`dafter_providers/batch.py`, Sarvam in `sarvam/batch.py`, vectors in `testdata/sarvam-batch/`) and posts a `transcript.version_created` envelope to `POST /sessions/{id}/transcripts`, which checks the envelope, its `transcriptHash` (RFC 8785 and SHA-256 with that field stripped, `HashWithout`/`hash_document(raw, field)`), the session's `configHash` and every recording and speaker against the store, then numbers it; a re-run is a new version, a retry of the same hash is the same one. `GET /sessions/{id}/transcripts` lists versions and `.../transcripts/{version}` exports one with its hash, both behind the worker credential too: it is the only credential the control plane verifies, its holder already reads the recordings and writes the versions, and a participant's media token never grants a transcript read. Tenant API keys (`docs/dafter.md`, tenancy) replace it for reads once they exist.
- The scribe (`python/dafter_scribe`, `docs/dafter.md` Context and memory) is a second AgentServer, hidden and publishing no track (`PERMISSIONS` in `worker.py`), subscribing to nothing. It reads `transcript.final`, `agent.note_taken` and `session.usage` from `dafter.events` only from a worker (`is_worker` in `listeners.py`: an agent participant, or a hidden one, which the control plane never makes a person) and only for its session, and publishes `scribe.notes` every `summaryIntervalMs` (the interval is also each rewrite's timeout; a failure keeps the last notes), `agent.turn_scored` (stage 4 `Judge`) and `scribe.minutes`. A person asks for minutes so far with `{"action":"minutes"}` on data topic `dafter.scribe`. When everyone leaves, `on_session_end` (`after_call`, bounded by `afterCallTimeoutSeconds`) writes the final minutes, stores them (`POST /sessions/{id}/minutes`, worker credential both ways, `minutes.go`), logs one `session cost` line and runs the stage 7 batch pass once no track recording is pending. The agent worker keeps the latest `scribe.notes` (`scribing.py`), re-briefs the agent with them between turns and offers `summarize_call`, `take_note`, `list_notes` only when the session has a scribe. Its LLM is config: Sarvam by default, profiles `scribe-gemini` and `scribe-nvidia` switch to the `google` and `nvidia` endpoint vendors; the default refs state only fields every vendor accepts, because a merge cannot delete a key. Both workers number their own envelopes from 0.
- Phone calls: `POST /sessions/{id}/call/start` with `{"to": "+E.164"}` dials into a stored session on the telephony channel, or on any other channel whose `telephony.phoneGuests` is `dial_out` or `both` (the session creator's choice of `off`, `dial_out`, `dial_in`, `both`, default `off`, and it must stay `off` on the telephony channel), once per call, each phone its own `p_` id. The trunk is the tenant's phone line (`tenants.<id>.telephony.trunk` in the catalog), never a profile's or a session's, and resolution drops the telephony block from every session that takes no phone (`dropIdleTelephony` in `resolve.go`, which refuses phone tuning in such a session by pointer), so the telephony channel's tuning never reaches a meeting; phone guests need a trunk and forbid e2ee, both at `/telephony/phoneGuests`, and a recorded meeting with them needs the agent (vectors in `testdata/telephony/`) (`go/internal/control/call.go`, `PlaceCall` in `transport/sip.go`, request pinned in `go/internal/transport/testdata/sip/`) on an inline trunk from the operator's table (`go/cmd/dafter-control/trunks.json`, or `DAFTER_TRUNKS`) that the stored `telephony.trunk` names; every per-account value of a trunk (address, numbers, credentials, inbound settings) is a `secret://` ref that resolves only to `<PROVIDER>_SIP_*`, and a trunk whose variables are all unset is left out, so the stack boots without a carrier. The phone joins as a minted `p_` id with `hidePhoneNumber`, and the number is never stored, logged or echoed in an error. `POST /sessions/{id}/call/{participantId}/stop` hangs one phone up: `HangUp` in `transport/hangup.go` removes the participant only when the room lists it as kind SIP, under a per-call `roomAdmin` token on that room (request pinned in `testdata/sip/`). The worker watches every SIP participant that joins, at any time, waits for its `sip.callStatus` `active` (bounded by the ringing timeout from its own join), then says the recording notice, not interruptible; on the telephony channel the first caller then hears the greeting, a meeting's phone guest only the notice (`PhoneLines` in `telephony.py`, `recording_notice` in `personas.py`). An always-mode session that takes calls never closes on disconnect and relinks to the next person (`Relink`). The test client's Create Session form sets Phone guests, and its in-meeting Phone guests section and tiles are `client-guests.js` and `guests.css`. Inbound never uses LiveKit's dispatch rules, which pick the room and name the caller `sip_` plus the number or its hash: Vobiz holds the caller in a conference while `POST /telephony/{trunk}/answer` (V3 signature required) stores the session and dispatches the agent, `.../held/{token}` (the token authenticates it; Vobiz does not sign every callback) dials the held caller back by calling `registrar.vobiz.ai:5060` as the Vobiz SIP Endpoint attached to the bridge application (digest credentials `VOBIZ_SIP_BRIDGE_USERNAME`/`PASSWORD`; `sip.vobiz.ai` answers `404 Trunk Not Found`) with the token as `X-VH-Bridge`, which Vobiz posts to the bridge answer URL as a form field, and `.../bridge` joins that leg to the same conference (`go/internal/control/inbound.go`, dialect in `go/internal/carrier/vobiz`, forms and XML pinned in its `testdata/`). Held calls and PIN attempts live in memory. Meeting dial-in (`dial_in`/`both`): a number in the trunk's `inbound.meetingNumbersRef` (`VOBIZ_SIP_MEETING_NUMBERS`; the rest answer the agent) answers with a `Gather` for the meeting PIN, and the signed `POST /telephony/{trunk}/pin` admits the caller into the running session's own room through the same hold, held and bridge path, no new session or dispatch (`control/meeting.go`); `telephony.dialIn.callerCheck` is `pin`, `pin_and_number` or `number`, every failure gets one uniform retry until `inbound.pinAttempts` (default 3). The control plane mints an 8-digit PIN per dial-in session at create, returns it as `dialIn` beside the token only to participants and presenters (`DisclosesDialInTo`), never in the document; allowed numbers come only through `PUT /sessions/{id}/dial-in/numbers`; both are stored as HMAC indexes (the PIN also sealed) under keys derived from `DAFTER_STATE_KEY` (`state/dialin.go`) and deleted once the room closes after opening, or after a day unopened (`SweepDialIns`, `control/dialin.go`). The test client's dial-in fields and line are `client-dialin.js`.

## Dev stack

`make dev` from a clean clone builds and starts everything: control plane, LiveKit SFU, Redis, MinIO (recordings), Jaeger (tracing), Prometheus, Grafana, and the Cloudflare tunnel only when `.env` sets `COMPOSE_PROFILES=tunnel` with its token (`.env.example`). `make dev-down` tears it all down. Config lives in `deploy/livekit.yaml` and `deploy/egress.yaml`; dev credentials are `devkey`/`secret`. The control plane is at `http://127.0.0.1:8080`. Recording storage reaches the control plane as `DAFTER_EGRESS_S3_*` (set in `docker-compose.yml` to match `deploy/egress.yaml`); without a bucket it boots and refuses recording starts. The egress container is on the host network, so it reaches the SFU and MinIO at `127.0.0.1`. MinIO no longer publishes public images, so `minio` and `minio-setup` run Chainguard's build, pinned by digest in `x-minio-image` because its free tier publishes only `latest`. It runs as uid 65532: a `minio-data` volume written by the old root image fails with "Unable to write to the backend" until `make dev-down` drops it. Disk use is capped for a local stack: `minio-setup` expires recordings after 1 day and sets a 2 GiB hard bucket quota (MinIO counts usage in a background scan, so it can overshoot for about a minute, and a recording that hits it fails), Prometheus keeps 2 days or 500 MB, Jaeger keeps 10000 traces in memory, and each container keeps two 10 MB log files (`x-logging`). `make dev-clean` also removes the stack's images (egress alone is 4.76 GB); the build cache is shared with other projects, so `docker builder prune` stays a manual step.

The SFU advertises `--node-ip` (`LIVEKIT_NODE_IP`, default 127.0.0.1) on the one published UDP port; anything else in `rtc` (a port range, `use_external_ip`) breaks local media, see the comments in `deploy/livekit.yaml`. LiveKit metrics are on port 6789, not 7880.

The `sip` compose service runs LiveKit's SIP bridge on the host network (`deploy/sip.yaml`, RTP 10000-10100) at log level warn, because at info it logs every dialed number. The `scribe` compose service (same image, `PACKAGE` build arg, its health port picked by the OS) runs the scribe beside it. The `agent` compose service runs the worker on the host network (like egress, so it reaches the SFU's advertised 127.0.0.1), its health port picked by the OS unless `DAFTER_AGENT_HTTP_PORT` names one (the framework's default, 8081, is the admin listener), and reads `SARVAM_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY` and `GEMINI_API_KEY` from `.env`. Agent state, each turn's latency by layer, the session's running INR cost, what the worker actually runs (LLM and effective fillers, backchannel and normalization, once at session start) and every stage failure with its error document (retried or given up) reach clients as `agent.state_changed`, `agent.turn_metrics`, `session.usage`, `agent.configured` and `provider.degraded` envelopes on the data channel topic `dafter.events` (prices come from `python/dafter_runtime/src/dafter_runtime/prices.csv`, verified rows only, an unlisted item is sent unpriced). With `DAFTER_METRICS_PORT` set the worker also serves them to Prometheus (`metrics.py`, scrape job `dafter-agent` at the compose network's pinned gateway 10.213.0.1, because `host.docker.internal` is the desktop machine on Docker Desktop) through the framework's own server in multiprocess mode, because turns run in job processes; labels are language, channel, stage and provider/model, never a session id, and a session creates every series it can produce at zero, or `rate()` loses its first observation. Endpointing comes before every framework layer (`FinalFirstSTT` holds end of speech until the final), so an STT adapter that holds it exposes `take_endpoint()` (`dafter_providers/endpointing.py`) and the row adds `endpointMs` and `replyGapMs`, both from the user's last voiced audio. livekit-agents keeps no assistant message for a reply stopped before its first synchronized word; the worker still reports that turn from `speech_created`. A turn whose first sentence reached TTS over 500 ms after the LLM's first token, while that sentence was under 80% of the reply, has gone serial: `agent.turn_metrics` says so in `serial` (rule in `timing.py`), the test client marks its row and Prometheus counts it. The framework publishes user and agent transcripts on the text stream topic `lk.transcription`. The test client's agent UI (selector, agent tile, invite/remove, live transcript, per-turn latency by layer beside the latency heard in the browser, running cost, refusals) lives in `go/cmd/dafter-control/agent.js`, `agent-call.js`, `agent-turns.js`, `agent-metrics.js`, `agent-refusal.js`, `agent-addressing.js` (dormant or awake, the Wake button) and `agent.css`, served from `clientAssets` in `main.go`; the transcription badge, the Captions panel and tile captions are `client-captions.js` and `captions.css`; the scribe's Notes panel, judge score and minutes on Leave are `client-scribe.js` and `scribe.css`. The rest of the client is `client.js` (SDK setup, e2ee, noise filters, media options), `client-stats.js`, `client-session.js`, `client-call.js`, `client-media.js` and `client-captions.js`, classic scripts sharing globals and loaded in that order after the agent files; new client code goes in files like these, not in `testclient.html`, and a new file needs both the `//go:embed` line and a `clientAssetPaths` entry. Load tests create sessions with the agent off. In an e2ee room the worker's SDK encrypts its data packets too (`dafter.events`, `lk.transcription`), so the pinned `livekit-client` must be 2.16 or newer and the key provider goes in `RoomOptions.encryption`, not the deprecated `e2ee`; an older client hears the agent but drops its state and transcript silently.

Load tests: `make loadtest` (HTTP only, token minting) and `make loadtest-media` (real WebRTC participants through `lk load-test`, knobs and pass criteria in `scripts/loadtest-media.sh --help`). `lk` must be the release binary `make tools` fetches into `go/bin`; a go-installed one embeds Git LFS pointers instead of video and publishes nothing. Grafana dashboards: `deploy/grafana/dashboards/dafter.json` (uid `dafter`, control plane and SFU), `dafter-agent-latency.json` and `dafter-agent-cost.json` (the worker); a uid change needs the grafana container recreated. The worker's metrics are new dashboards rather than panels in `dafter.json`, which is already past the 500-line cap.

## Agent rules

These override default behavior. Project config wins on conflict with global rules; otherwise both apply.

1. **Tool only.** Do only the task given. No suggestions, follow-ups, interpretations, advice, or assumptions. Do not automatically initiate tests, dev servers, migrations, or anything not explicitly instructed.
2. **User-level rules followed religiously.** Every rule in the user's global config (`~/.claude/CLAUDE.md`, `RULES.md`, `TOOLING.md`) must be followed without mistakes.
3. **Project files stay in this folder and are gitignored.** All project-related memory, temp files, and scratchpad are maintained inside this folder only, gitignored.
4. **Tooling routing.** Plans through `lavish-axi`. Tasks through `tasks-axi`. GitHub through `gh-axi`. All tasks are subagent-driven on a new terminal, never on the main thread.
5. **Explicit bypass is single-message only.** A rule bypass applies only to the current message. On the next message, all rules apply again. A bypass never carries over.
6. **No comments in code.** Names and structure carry the context. Tool directives (`//go:`, `//nolint`, `# noqa`, `# type:`, shebangs, generated-code headers) are the only exception.
7. **500 lines per file, hard cap.** A file that would pass 500 lines is split before it does.
